# 公開サイト運用・データ契約

最終監査: 2026-09-14

## 公開範囲と責任分界

- 正規 URL: <https://soichirow.github.io/edh-hareruya/>
- 公開元: GitHub リポジトリ `soichirow/edh-hareruya` の `main/docs`
- サイト所有者: リポジトリ所有者
- 問い合わせ窓口: 未整備（公開前提の連絡先を決めてサイトへ掲載する）
- フロントエンド、GAS、Spreadsheet は独立した変更単位として扱う

| 変更対象 | 反映方法 | 本番確認 |
|---|---|---|
| `docs/` | `main` に push し GitHub Pages の反映を待つ | デプロイ対象 SHA と公開ページを確認 |
| `gas/` | clasp で同期後、GAS のデプロイ版を更新 | 実行中のバージョンと JSON API を確認 |
| `データベース` シート | セル更新時に即時反映 | 行列数、ヘッダー、API 応答、画面を確認 |

`gas/.clasp.json`、認証情報、API キーはコミットしない。GitHub Pages の push を GAS の公開、GAS の push をデプロイ版更新とみなしてはいけない。

## Spreadsheet の契約

本番の `データベース` シートは A:AC の29列で、順序と表記も API 契約の一部です。

| 列 | ヘッダー | 列 | ヘッダー | 列 | ヘッダー |
|---|---|---|---|---|---|
| A | 動画タイトル | K | プレゼンター | U | カードタイプ |
| B | ID | L | 紹介カード | V | オラクルテキスト |
| C | 公開日(UTC) | M | 関連する統率者 | W | Power |
| D | 公開日(JST) | N | 関連する統率者2 | X | Toughness |
| E | 動画URL | O | 関連カード | Y | Colors |
| F | サムネイルURL | P | テーマ | Z | Color Identity |
| G | 再生時間 | Q | 上位互換？ | AA | 画像URL |
| H | 話数 | R | カード名 (日本語) | AB | Scryfall |
| I | 紹介順 | S | カード名 (英語) | AC | CMC |
| J | 今のうちだぞ | T | マナコスト |  |  |

画面の色判定は `Color Identity`、マナ総量の絞り込みとソートは数値化した `CMC` を使う。両面カードを含め、Scryfall から取得した値と一致させる。

28列で CMC を持たず、`画像URL` と `Scryfall` の位置も異なる旧コピーシートを本番へ上書きしない。

## 安全なデータ更新

1. 対象シート名、29列、ヘッダー順、更新前の行数を記録する。
2. Spreadsheet の版履歴で復元可能なことを確認する。
3. カード名をキーに Scryfall の正式データを取得し、R:AC だけを対象にする。
4. 行数や動画列 A:Q が変わっていないこと、カード名と取得結果の対応を確認する。
5. API の HTTP 200、配列件数、名前付き行の CMC 欠損数を確認する。
6. キャッシュを避けた公開 E2E で色、CMC 絞り込み、CMC 昇順・降順、画像表示を確認する。

大量更新では、対象セルの更新前スナップショットを保持し、対象外セルが不変であることを比較する。結果不明の更新を推測で再実行しない。

## 公開時チェック

- `npm test` と `npm run lint` が成功する。
- canonical、`robots.txt`、`sitemap.xml` が正規 URL を指す。
- スマートフォン幅とデスクトップ幅で主要操作を確認する。
- GitHub Pages が対象コミットを公開したことを確認してから完了とする。
- GAS 変更時はクラウド側 Head、デプロイ版、API 応答を別々に確認する。
- GA4 は拒否時に読み込まれず、同意後だけ読み込まれることを確認する。

## Analytics・プライバシー・検索

- GA4 測定 ID はフロントエンドに設定済み。初期状態は `analytics_storage: denied` で、同意後にだけタグを読み込む。
- 同意状態、お気に入り、言語、テーマ、API キャッシュをブラウザーの localStorage に保存する。
- GA4 管理画面での受信、Google Search Console、Bing Webmaster Tools の登録状態は、この監査では未確認。
- カード画像とカード情報は Scryfall、動画リンクは YouTube、アクセス解析は Google に接続する。

## 既知のリスク

1. **高: GAS テストが本体を直接実行していない。** `tests/gas-adapter.js` は本体ロジックを381行再実装しており、リトライ条件やアクセスログなどが `gas/` とずれている。テスト成功だけで本番 GAS の正しさを判断しない。
2. **高: ローカル GAS とクラウド Head に差分がある。** クラウド側を pull・比較せずローカルから push すると、他の修正を上書きし得る。
3. **中: API 障害時に古いキャッシュを無期限表示し得る。** キャッシュ時刻は保存されるが期限判定に使われず、更新失敗は画面に残らない。
4. **中: JSON API の各アクセスが Spreadsheet に1行追記する。** `アクセスログ` の増加量とシート上限を定期確認する。
5. **低: `CACHE_TTL` は未使用。** 実装上の期限保証と誤認しない。
6. **低: 公開問い合わせ窓口がない。** 運用者が継続公開する場合は、個人情報を出さずに使える連絡方法を用意する。

最優先の改善は、GAS の写経テストをやめ、実ファイルを最小の VM ハーネスで読み込むこと。新しいテストフレームワークや依存関係は不要。

## 復旧

- フロントエンド: 不具合コミットを Git で revert し、Pages の再反映と公開 E2E を確認する。
- GAS: 直前の正常なデプロイバージョンへ戻す。Head の編集だけでは公開版は戻らない。
- Spreadsheet: 版履歴または更新前スナップショットから対象セルだけを戻し、29列契約と API 件数を再確認する。
